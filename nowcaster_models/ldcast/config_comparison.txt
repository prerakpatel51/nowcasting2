LDCast Config Comparison
========================

All configs share the same data, patches, pipeline, and split settings.
Only the differences are shown below.


WHY WE CHANGED THE NORMALIZATION (mean/std)
--------------------------------------------

Diffusion models generate outputs by iteratively denoising Gaussian noise. This
means the model operates most naturally in the range of roughly -3 to +3 standard
deviations (sigma) from the mean. Values beyond ~4 sigma are extremely rare in a
Gaussian and essentially unreachable for the model to produce. The normalization
statistics (mean and std) control where different precipitation intensities land
in this sigma space. If the rain/dry boundary falls deep in the negative tail
(as with the original stats: dry at -4.48 sigma), the model's noise floor sits
above the boundary and everything gets mapped to rain — causing overprediction.
If real precipitation gets pushed into the far positive tail (as with v1 stats:
moderate rain at +5.36 sigma), the model simply cannot generate values that high
— causing underprediction. The v3 normalization (mean=-1.0, std=0.55) solves this
by centering the rain/dry threshold at exactly 0 sigma, placing dry pixels at
-1.82 sigma and heavy rain at +3.64 sigma. This puts the entire precipitation
range within the diffusion model's natural operating window.

The dry_bin_weight was set to 0.0 (uniform sampling) in v3 because the balanced
normalization removes the need for artificial oversampling of dry patches. In the
original configs, dry pixels sat at -4.48 sigma where the model could not easily
distinguish them from light rain, so we tried overweighting dry samples (0.35 in
v1, 0.20 in v2) to force the model to learn the dry state. With v3, the dry/rain
boundary is at 0 sigma — the point of maximum model sensitivity — so the model
naturally learns to separate dry from rain without needing a sampling bias. Keeping
dry_bin_weight > 0 with v3 normalization would actually hurt by reducing the
model's exposure to the rain intensities we care about forecasting.

5. REGULARIZATION & TRAINING IMPROVEMENTS (v1/v2/v3 only)
----------------------------------------------------------

  Setting               smallest/small/large   improved (v1)   improved_v2   improved_v3
  -------               --------------------   -------------   -----------   -----------
  use_groupnorm         false (absent)         true            true          true
  dropout               0.0 (absent)           0.1             0.1           0.1
  beta_schedule         linear (default)       cosine          cosine        cosine
  clip_denoised         false (absent)         true            true          true
  clip_range            N/A                    [-5.0, 4.0]     [-5.0, 3.5]   [-2.5, 4.5]

  GroupNorm:   Stabilizes UNet activations, prevents noise prediction drift
  Dropout:     Regularizes denoiser, reduces overfitting (train/val gap narrowed)
  Cosine:      More uniform noise distribution across timesteps
  Clipping:    Constrains pred_x0 during PLMS sampling to valid range
